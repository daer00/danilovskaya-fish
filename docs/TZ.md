# Техническое задание: Даниловская рыба

**Версия:** 1.1  
**Продукт:** Telegram-бот + веб-админка для недельного предзаказа рыбы (закупка в воскресенье, выдача в церкви).  
**Базовый каркас:** инфраструктура из [vlad4endev/chehlii](https://github.com/vlad4endev/chehlii) (FastAPI, Postgres, Redis, aiogram 3, React-админка, Docker). Домен чехлов **не** переносится — переписывается под партии и корзину.

---

## 1. Цель и границы MVP

### Цель
Клиенты оформляют заказ рыбы в Telegram до дедлайна. Админы ведут каталог, партии, заказы и сводку к закупке в браузере. Оплата при получении (нал / перевод).

### В MVP
- Telegram-бот (каталог кнопками в чате, без mini-app)
- Веб-админка: партии, товары, заказы, сводка, тексты бота
- Недельная **партия** (дедлайн, дата выдачи, открыт/закрыт)
- Корзина, половины рыбы (шаг 0,5), оплата при получении
- Уведомления клиенту и админам (см. тексты бота)
- Деплой: Beget VPS + long polling + `TG_PROXY`

### Вне MVP
- Mini-app / MAX-бот
- Онлайн-оплата (Robokassa и др.)
- Доставка курьером
- Учёт расходников, P&L, мониторинг рынка (остаются в Excel)
- Шаг количества 0,25 (в Excel уже бывает; позже — флаг товара)

## 2. Роли

| Роль | Канал | Возможности |
|------|--------|-------------|
| Клиент | Telegram | Каталог, заказ, «Мои заказы», отмена до дедлайна (если статус позволяет) |
| Админ | `/admin` + Telegram-чат уведомлений | CRUD партий/товаров, статусы заказов, сводка, тексты бота |

---

## 3. Сущности

### Batch (партия)
- `deadline` — до какого момента принимают заказы
- `pickup_date` — дата выдачи
- `pickup_place` — по умолчанию «холл»
- `is_open` — приём открыт
- Связь с активными товарами партии (или глобальный каталог + флаг активности)

### Product (товар)
- `name` — с весом в названии при необходимости («Форель свежая ~2,5 кг»)
- `price` — цена **за 1 рыбу** (₽)
- `description`
- `photo_url` (опционально)
- `allow_halves` — шаг 0,5 или только целые
- `is_active`

### Client
- `telegram_id`, имя, телефон

### Order + OrderItem
- Номер заказа, статус, комментарий, сумма
- Позиции: товар, количество (Decimal, шаг 0,5 при `allow_halves`)

### BotMessage
- Код сообщения + текст с плейсхолдерами (редактирование в админке)

### OutboundMessage
- Очередь исходящих в Telegram (backend → бот)

## 4. Статусы заказа

| В системе | Клиенту |
|-----------|---------|
| `new` | Принят, ждёт подтверждения |
| `confirmed` | Подтверждён |
| `ready` | Готов к выдаче |
| `completed` | Получен |
| `cancelled` | Отменён |

Переходы (админ): `new` → `confirmed` → `ready` → `completed`; из `new`/`confirmed` → `cancelled` (с опциональной причиной).  
Клиент может отменить сам только до дедлайна и только если статус `new` (после `confirmed` — писать админам).

## 5. Сценарии бота

Полные тексты: [Тексты_бота_v1_1.md](../Тексты_бота_v1_1.md).

1. `/start` — приветствие / возвращение; кнопки Каталог · Мои заказы · Условия  
2. Каталог активной партии → карточка → количество → корзина  
3. Оформление: ФИО → телефон → комментарий → подтверждение → номер заказа  
4. Мои заказы / отмена по правилам  
5. После дедлайна — сообщения «приём закрыт»  
6. Уведомления: ready, cancelled; админам: новый заказ, отмена, −2ч, сводка партии  

---

## 6. Админка (экраны MVP)

1. Вход (JWT)
2. Партии — создать/открыть/закрыть, дедлайн, дата выдачи
3. Товары — CRUD, цена за рыбу, `allow_halves`, фото, активность
4. Заказы — фильтр по партии, смена статуса, причина отмены
5. Сводка к закупке — агрегат qty по товарам активной партии
6. Тексты бота — редактирование `BotMessage`

## 7. Плейсхолдеры

`{имя}`, `{сумма}`, `{дедлайн}`, `{дата_выдачи}`, `{номер}`, `{состав}`, `{товар}`, `{цена}`, `{количество}`, `{причина}`, `{описание}`, `{статус}`, `{телефон}`, `{комментарий}`, `{сводка}`

Менять можно текст вокруг; сами плейсхолдеры — нет.

## 8. Стек и инфраструктура

- Backend: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL 16
- Redis 7 — FSM бота
- Bot: aiogram 3, **long polling**, `TG_PROXY`
- Frontend admin: React + Vite
- Docker Compose; CI: GitHub Actions
- Хостинг: **Beget VPS** (Docker) + зарубежный прокси только для `api.telegram.org`
- Секреты в `.env` на сервере, не в git
